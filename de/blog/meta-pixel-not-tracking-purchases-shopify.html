Ihr Meta Pixel wird ausgelöst. Ihre Käufe tauchen trotzdem nicht auf.

Kamran Arshad12. Aug. 20269 Min. Lesezeit

Wenn Ihr Meta Pixel lädt, aber nie Käufe erscheinen, prüfen Sie in dieser Reihenfolge: zwei gleichzeitig installierte Pixel, das Pixel fehlt auf der echten Bestätigungsseite, ein Purchase-Event ohne value und currency, eine externe Zahlungsweiterleitung, die die Sitzung abbricht, und die Deduplizierung gegen einen Conversions-API-Datenstrom.

Das Erste ist das Häufigste und am schwersten zu erkennen, weil nichts kaputt aussieht.

„Das Pixel wird ausgelöst“ und „meine Käufe werden getrackt“ sind zwei verschiedene Aussagen, und in der Lücke dazwischen versickert das meiste Shopify-Werbebudget. Ein grüner Pixel Helper sagt Ihnen, dass ein Pixel auf der Seite existiert. Er sagt nichts darüber, ob das richtige Event mit den richtigen Parametern beim richtigen Pixel angekommen ist.

Fangen Sie hier an: Haben Sie mehr als ein Pixel?

Das ist das Erste, was ich in jedem Konto prüfe, und es ist das Problem, das ich tatsächlich in der Praxis gefunden habe, statt nur darüber zu lesen.

In einem Shop, den ich geprüft habe, waren zwei Pixel gleichzeitig installiert, eines über die Shopify-Integration, eines direkt im Theme eingefügt. Beide funktionierten technisch. Beide meldeten. Keines meldete alles, weil sich die Events je nach Laden der Seite zwischen beiden aufteilten.

Dass das so lange überlebt, liegt daran, dass es nie kaputt aussieht. Es gibt keinen Fehler. Pixel Helper zeigt grün. Der Events Manager zeigt Käufe, nur weniger, als Sie tatsächlich hatten. Und solange Sie das Pixel nicht mit der eigenen Bestellzahl von Shopify abgleichen, haben Sie keinen Grund zu vermuten, dass die Zahl nur ein Bruchteil ist.

Was ich hier behaupten kann und was nicht

Ich habe das in einem Kundenshop gefunden, und die Korrektur hat verändert, was die Berichte zeigten. Ich werde der Verbesserung keinen Prozentsatz zuordnen, denn ehrlich gesagt hängen aufgeteilte Attribution und Budgetverschwendung zusammen, sind aber nicht identisch, und ich gebe Ihnen lieber den Mechanismus als eine Zahl, die ich nicht vollständig verteidigen kann.

Auf den Mechanismus kommt es sowieso an: Zwei Pixel heißt, dass jedes nur einen Teil der Wahrheit sieht, und Meta optimiert auf das, was es sieht.

So prüfen Sie es

Schauen Sie im Shopify-Adminbereich an drei Stellen nach, denn ein Pixel kann an jeder davon installiert sein, und nichts warnt Sie vor den anderen:

  • Einstellungen → Kundenereignisse: Hier liegen benutzerdefinierte Pixel
  • Facebook & Instagram Vertriebskanal: die offizielle Integration
  • Onlineshop → Themes → Code bearbeiten: theme.liquid nach fbq oder connect.facebook.net durchsuchen

Wenn Sie an mehr als einer dieser Stellen eine Pixel-ID finden, ist das Ihr Problem. Wählen Sie eine Methode, meist ist der Vertriebskanal die richtige, und entfernen Sie die anderen.

Der Rest der Reihenfolge

02

Das Pixel ist nicht auf der Seite, die der Kunde tatsächlich erreicht

Alle installieren seitenweit und nehmen an, dass die Bestätigungsseite das erbt. Oft tut sie es nicht, weil diese Seite außerhalb Ihres Themes gerendert werden kann. Wenn Sie Upsells nach dem Kauf nutzen, ist die Seite, die ein Kunde direkt nach dem Bezahlen sieht, vielleicht nicht die, die Sie für die Danke-Seite halten.

Der CheckSchließen Sie eine echte Bestellung ab. Sehen Sie auf der Seite, auf der Sie landen, den Quelltext an und suchen Sie nach Ihrer Pixel-ID. Leiten Sie es nicht vom Theme ab.
03

Das Purchase-Event wird ohne seine Pflichtparameter ausgelöst

Ein Purchase-Event ohne value und currency ist fast nutzlos. Meta kann nicht auf Umsatz optimieren, von dem es nie erfahren hat, und wertbasierte Gebote haben nichts, womit sie arbeiten können. Fehlende content_ids brechen zusätzlich das Katalog-Matching und dynamisches Retargeting.

Der CheckFiltern Sie im Network-Tab nach facebook und lesen Sie den Query-String des Purchase-Requests. Prüfen Sie, ob value, currency und content_ids vorhanden und befüllt sind.
04

Der Checkout verlässt Ihre Domain, und die Sitzung bricht ab

Wenn die Zahlung an ein externes Gateway übergeben wird und der Kunde auf eine Bestellbestätigungsseite zurückkehrt, kann dieser Umweg die Browsersitzung abbrechen, von der das Pixel abhängt. Die Bestellung wird abgeschlossen, das Event kommt nicht an oder kommt ohne die Kennungen an, die für die Zuordnung nötig sind.

Der CheckVerlässt Ihr Zahlungsablauf Ihre Domain? Wenn ja, ist reines Browser-Tracking nur ein Versuch, und Sie brauchen die Conversions API.
05

Die Deduplizierung entfernt das Event absichtlich

Wenn Sie Pixel und Conversions API zusammen betreiben (was Sie sollten), dedupliziert Meta anhand der event_id. Wenn Browser und Server sich bei dieser ID nicht einig sind, zählen Sie entweder alles doppelt oder verlieren still eine Seite. Eine Seite zu verlieren sieht genauso aus wie „das Pixel funktioniert nicht mehr“.

Der CheckErfassen Sie für eine Bestellung die event_id, die der Browser gesendet hat, und die, die Ihr Server gesendet hat. Sie müssen identisch sein.
06

Werbeblocker und Tracking-Schutz

Ein spürbarer Teil des Traffics blockiert browserbasiertes Tracking komplett. Das ist kein Fehler, den Sie beheben können, sondern eine dauerhafte Steuer auf clientseitige Messung, und der Grund, warum ein reines Browser-Setup immer zu wenig zählt. Die Lösung ist keine Reparatur, sondern die Conversions API.

Der CheckVergleichen Sie die Käufe im Events Manager mit der Bestellzahl in Shopify für denselben Zeitraum. Eine dauerhafte Lücke, die mit dem Volumen wächst, ist meist genau das.
07

Sie schauen zu früh

Die Berichte im Events Manager sind nicht sofort da. Bevor Sie schließen, dass ein Event fehlt, warten Sie ein paar Stunden und schauen erneut. Ich habe Leute einen funktionierenden Checkout neu schreiben sehen, weil sie neunzig Sekunden nach einer Testbestellung in ein Dashboard geschaut haben.

Der CheckNutzen Sie das Tool „Test-Events“ für sofortiges Feedback und den Events Manager für das Volumen, am nächsten Tag.

Der Abgleich, den niemand macht

Hier ist die Übung, die Probleme findet, die keine Checkliste findet. Wählen Sie eine Woche. Notieren Sie drei Zahlen:

QuelleWas sie zähltErwartetes Verhältnis
Shopify-BestellungenJede bezahlte Bestellung, PunktDie Wahrheit
Käufe im Meta Events ManagerEmpfangene Purchase-EventsSollte sich Shopify annähern, nie darüber liegen
Conversions im Meta Ads ManagerKäufe, die Meta den Anzeigen zuschreibtEine Teilmenge, nicht alle Verkäufe kommen über Anzeigen

Die meisten vergleichen das falsche Paar und geraten in Panik. Die Conversions im Ads Manager sollten niedriger sein als die Shopify-Bestellungen, weil nicht jeder Kunde über eine Anzeige kam. Die Zahl, die nahe an Shopify liegen sollte, sind die Käufe im Events Manager. Liegt sie weit unter Ihrer Bestellzahl, haben Sie ein Tracking-Problem und keine Attributionsfrage.

Und wenn der Events Manager höher ist als Shopify, haben Sie das umgekehrte Problem, meist doppelte Events, und das ist ein anderer Artikel.

Was ich Ihnen nicht sage

Ich nenne Ihnen keinen erwarteten Abweichungsprozentsatz, denn die ehrliche Spanne hängt von Ihrem Traffic-Mix, Ihrem Checkout, den Browsern Ihrer Kunden und Ihrem Land ab, und jeder veröffentlichte Benchmark, den ich gesehen habe, stammt von einer Firma, die die Lösung verkauft. Ermitteln Sie Ihre eigene Ausgangslage, wenn alles funktioniert, und werten Sie die Abweichung von Ihrer Zahl als Signal.

Die Reihenfolge oben spiegelt eine kleine Zahl von Konten wider, plus das, was die Fehlerarten logisch nahelegen. Verstehen Sie sie als sinnvolle Suchreihenfolge, nicht als Statistik.
