Sie haben CAPI installiert und Ihr Umsatz hat sich verdoppelt. Hat er nicht.

Kamran Arshad12. Aug. 20268 Min. Lesezeit

Doppelte Käufe nach der Installation der Conversions API bedeuten fast immer eines: Browser und Server senden für denselben Kauf unterschiedliche event_id-Werte. Meta dedupliziert anhand übereinstimmender event_name plus event_id. Weichen die IDs ab, kann Meta nicht wissen, dass beide Events dieselbe Bestellung sind, und zählt beide.

Gefährlich ist der umgekehrte Fehler, bei dem IDs kollidieren und Sie still und leise echte Verkäufe verlieren.

Die Conversions API zu installieren ist die richtige Entscheidung. Browser-Tracking verliert Events durch Werbeblocker, Tracking-Schutz, abgebrochene Sitzungen und nicht fertig geladene Seiten, und ein serverseitiger Datenstrom holt einen guten Teil davon zurück. Fast jeder sollte beides betreiben.

Aber „beides betreiben“ heißt, dass Meta jeden Kauf zweimal gemeldet bekommt, und das Einzige, was eine doppelte Zählung verhindert, ist eine gemeinsame Kennung. Liegt diese Kennung in die eine Richtung falsch, verdoppelt sich Ihr Umsatz auf dem Papier. Liegt sie in die andere Richtung falsch, halbiert sich Ihr Umsatz still und leise.

Wie Deduplizierung tatsächlich funktioniert

Meta gleicht zwei Felder gemeinsam ab: event_name und event_id. Beide müssen übereinstimmen.

✗ Doppelt gezählt
Browser:
  event_name: "Purchase"
  event_id:   "a91f-2026-08-12"

Server:
  event_name: "Purchase"
  event_id:   "1047"
✓ Zu einem dedupliziert
Browser:
  event_name: "Purchase"
  event_id:   "order_1047"

Server:
  event_name: "Purchase"
  event_id:   "order_1047"

Die Regel ist einfach formuliert und in der Praxis leicht zu brechen, weil die beiden Seiten meist von verschiedenen Systemen zu verschiedenen Zeiten gebaut werden. Das Browser-Event erzeugt ein Theme oder ein Tag Manager, das Server-Event eine App, ein Middleware-Dienst oder Ihr eigener Code. Nichts zwingt sie zur Übereinstimmung, und nichts warnt Sie, wenn sie nicht übereinstimmen.

Eine Kennung wählen, die nicht abweichen kann

Die Kennung muss pro Bestellung eindeutig und auf beiden Wegen identisch sein. Diese zwei Anforderungen schließen das meiste aus, wonach man zuerst greift.

Zeitstempel sind der schlimmste Kandidat und der verlockendste, weil sie eindeutig aussehen. Das sind sie nicht: Zwei Bestellungen in derselben Sekunde kollidieren, und die Uhr des Browsers ist nicht die Uhr Ihres Servers. Eine UUID ist nur in Ordnung, wenn sie einmal erzeugt und dann an die andere Seite weitergegeben wird. Wenn jede Seite ihre eigene erzeugt, haben Sie eine Duplizierungsmaschine gebaut.

Der subtilere Fehler: stiller Verlust

Alle sorgen sich um doppelte Zählung, weil sie sichtbar ist. Der schlimmere Fehler ist eine Kennung, die nicht eindeutig ist: eine Checkout-ID, die über Bestellungen hinweg wiederverwendet wird, oder ein Wert, der sich wiederholt. Dann dedupliziert Meta korrekterweise zwei tatsächlich verschiedene Käufe zu einem, und Ihnen fehlt echter Umsatz im Reporting, ohne dass irgendwo ein Fehler erscheint.

Doppelte Zählung sieht nach guten Nachrichten aus und wird untersucht. Stiller Verlust sieht nach langsamem Rückgang aus und wird den Anzeigen angelastet.

Beweisen, dass es funktioniert, statt es anzunehmen

Konfiguriert ist nicht dasselbe wie funktionierend. Hier ist der Test, der es klärt, und er dauert etwa fünfzehn Minuten.

  1. Eine echte Bestellung aufgebenEin echter Kauf über den echten Checkout, kein Testlink. Notieren Sie die Bestellnummer.
  2. Die Event-ID im Browser erfassenÖffnen Sie vor dem Checkout die DevTools, filtern Sie den Network-Tab nach facebook, schließen Sie die Bestellung ab und lesen Sie die eventID im Purchase-Request.
  3. Die Event-ID auf dem Server erfassenSuchen Sie in den Logs Ihrer CAPI-Integration oder im Events Manager das serverseitige Event zu derselben Bestellung und lesen Sie dessen event_id.
  4. Zeichen für Zeichen vergleichenNicht ähnlich. Identisch. Ein Präfix auf einer Seite (order_1047 gegenüber 1047) ist ein Fehler, kein Detail.
  5. Die Deduplizierungsberichte prüfenÖffnen Sie im Events Manager das Purchase-Event und sehen Sie nach, wie es empfangen wird. Ein korrekt dedupliziertes Setup zeigt Browser und Server als Quellen für dasselbe Event, nicht zwei getrennte Summen.
  6. Eine ganze Woche abgleichenVergleichen Sie die Bestellzahl Ihres Shops mit den Käufen im Events Manager für eine abgeschlossene Woche. Deutlich über Ihrer Bestellzahl bedeutet Duplizierung. Deutlich darunter bedeutet Verlust.

Die Zahl, die zeigt, dass es funktioniert

Sobald die Deduplizierung stimmt, lohnt sich der Blick auf die Event Match Quality. Sie zeigt, wie viele identifizierende Informationen Sie mit jedem Event senden: gehashte E-Mail, Telefonnummer, Name, Standort, Klick-Kennungen. Sie bestimmt, wie gut Meta eine Conversion der Person zuordnen kann, die die Anzeige gesehen hat.

Genau hier zahlt sich die Conversions API aus. Ihr Server kennt die E-Mail-Adresse und Telefonnummer des Kunden, weil er gerade etwas gekauft hat. Der Browser oft nicht. Diese Daten serverseitig und korrekt gehasht zu senden, ist meist ein größerer Gewinn, als die blockierten Events zurückzuholen.

Hashen, und prüfen, dass Sie es getan haben

Kundenkennungen müssen vor dem Senden mit SHA-256 gehasht werden. Das ist keine Leistungsfrage, sondern der Unterschied zwischen einem Hash und den rohen personenbezogenen Daten Ihrer Kunden, die Sie an Meta schicken. Wenn Sie die Integration selbst bauen, prüfen Sie das Hashing an einem echten Payload, bevor Sie live gehen, denn ein Fehler hier ist ein Datenschutzvorfall und kein Tracking-Fehler.

Was ich nicht behaupte

Ich nenne Ihnen keinen Zielwert für die Event Match Quality und keine erwartete Steigerung durch CAPI. Beides hängt vollständig davon ab, welche Kundendaten Sie rechtmäßig erheben dürfen, von Ihrem Checkout und von Ihrem Traffic, und jeder veröffentlichte Benchmark, den ich gesehen habe, stammt von einem Anbieter, dessen Produkt genau die gemessene Zahl verbessert.

Messen Sie Ihre eigene Ausgangslage vor der Änderung, messen Sie erneut, nachdem sie ein volles Attributionsfenster gelaufen ist, und vergleichen Sie mit sich selbst. Dieser Vergleich ist mehr wert als jeder veröffentlichte Durchschnitt.
