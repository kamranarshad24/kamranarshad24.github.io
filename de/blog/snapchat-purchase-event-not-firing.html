Snapchat Purchase Events werden nicht ausgelöst: die Diagnose-Reihenfolge

Kamran Arshad12. Aug. 20269 Min. Lesezeit

Wenn Ihr Snap Pixel lädt, aber PURCHASE nie im Events Manager erscheint, liegt es fast immer an einer von sechs Ursachen: ein kleingeschriebener Event-Name, eine fehlende transaction_id, das Pixel fehlt auf der echten Bestätigungsseite, eine externe Zahlungsweiterleitung bricht die Sitzung ab, ein Single-Page-Checkout initialisiert das Pixel neu, oder Events werden gegen einen Conversions-API-Datenstrom wegdedupliziert.

Gehen Sie sie in dieser Reihenfolge durch. Die ersten drei erklären das meiste, was ich finde.

Über Snapchat-Tracking wird weit weniger geschrieben als über Meta oder Google. Wenn es kaputtgeht, sind Sie also meist auf sich allein gestellt. Die vorhandenen Artikel stammen oft von Firmen, die ein Tracking-Produkt verkaufen, und hören deshalb bei „installieren Sie unsere App“ auf. Hier ist die Abfolge, die ich tatsächlich durchgehe, in meiner Reihenfolge, und warum diese Reihenfolge.

Zuerst: bestätigen, dass das Event wirklich nicht ankommt

Bevor Sie etwas ändern, klären Sie, ob das Event fehlt oder nur verzögert ist. Zwei Checks, sechzig Sekunden.

Prüfen Sie das Netzwerk, nicht das Dashboard. Öffnen Sie Ihre Bestätigungsseite in Chrome, öffnen Sie die DevTools (F12), gehen Sie zum Tab Network und filtern Sie nach tr.snapchat.com. Schließen Sie einen echten Testkauf ab. Sehen Sie einen Request mit Ihrer Pixel-ID und dem Event-Namen, erledigt der Browser seine Arbeit, und Ihr Problem liegt weiter hinten: Reporting, Deduplizierung oder Attribution. Wird nichts ausgelöst, liegt das Problem auf der Seite.

Die Browsererweiterung Snap Pixel Helper erledigt dasselbe mit einer freundlicheren Oberfläche und zeigt Ihnen auch, ob das Pixel überhaupt installiert ist. Ich nutze den Network-Tab, weil er den genauen Payload zeigt, und im Payload steckt meist die Antwort.

Geben Sie ihm Zeit, bevor Sie in Panik geraten

Die Berichte im Events Manager sind nicht sofort da. Bevor Sie schließen, dass ein Event fehlt, warten Sie ein paar Stunden und prüfen erneut. Ich habe Leute einen funktionierenden Checkout neu schreiben sehen, weil sie neunzig Sekunden nach einer Testbestellung in ein Dashboard geschaut haben.

Die sechs Ursachen, nach Häufigkeit

01

Der Event-Name ist kleingeschrieben

Die Standard-Events von Snapchat sind großgeschrieben: PURCHASE, ADD_CART, PAGE_VIEW, START_CHECKOUT. Wenn Sie purchase senden, wird es nicht als Standard-Event erkannt. Das Tückische: Es kann trotzdem ausgelöst werden und irgendwo erscheinen, wird aber nicht als Standard-Conversion behandelt. Kampagnenoptimierung und Reporting verhalten sich dann so, als wäre nichts passiert.

Das steht auf Platz eins, weil es genau das Symptom erzeugt, das Leute beschreiben, „das Pixel wird ausgelöst, aber der Events Manager zeigt nichts“, und weil es naheliegt, eine Meta-Implementierung einfach zu übernehmen. Meta verwendet Purchase. Snapchat nicht.

✗ Von Meta übernommen
{
  event: "Purchase",
  price: 24.00,
  currency: "USD"
}
✓ Was Snapchat erwartet
{
  event: "PURCHASE",
  price: 24.00,
  currency: "USD",
  transaction_id: "1047"
}
Der CheckLesen Sie im Network-Tab den Event-Namen im Request-Payload. Er muss genau PURCHASE lauten. Großschreibung ist hier keine Kosmetik.
02

Es wird keine transaction_id gesendet

Ohne transaction_id kann Snapchat eine echte zweite Bestellung nicht davon unterscheiden, dass derselbe Kunde die Bestätigungsseite neu lädt. Snap dokumentiert ein Deduplizierungsfenster von 30 Tagen für transaction_id, gegenüber 48 Stunden für client_dedup_id.

Der Fehler wirkt in beide Richtungen, deshalb steht er so weit oben. Lassen Sie sie weg, blähen Neuladevorgänge Ihre Kaufzahl auf. Senden Sie einen Wert, der nicht wirklich pro Bestellung eindeutig ist (eine Warenkorb-ID, eine Checkout-ID, eine Sitzungs-ID), werden echte Bestellungen zu einer zusammengefasst und verschwinden. Der zweite Fall sieht genau so aus wie „meine Events werden nicht ausgelöst“.

Der CheckGeben Sie zwei Testbestellungen auf. Prüfen Sie, ob sich die transaction_id zwischen beiden unterscheidet und ob sie der Bestellnummer entspricht, die Ihr Shop tatsächlich vergibt.
03

Das Pixel ist nicht auf der Seite, die die Bestellung tatsächlich bestätigt

Fast alle installieren das Pixel seitenweit und nehmen an, dass die Bestätigungsseite es erbt. Oft tut sie es nicht. Gehostete Checkouts, Bestellstatus-Seiten und Upsell-Abläufe nach dem Kauf werden häufig außerhalb des Themes oder Templates gerendert, das Ihren Tracking-Code enthält.

Gezielt prüfen sollten Sie: Wenn Sie einen Upsell nach dem Kauf nutzen, ist die Seite, auf der ein Kunde direkt nach dem Bezahlen landet, vielleicht nicht die Seite, die Sie für die Danke-Seite halten.

Der CheckSchließen Sie eine echte Bestellung ab. Sehen Sie auf der Seite, auf der Sie landen, den Quelltext an und suchen Sie nach Ihrer Pixel-ID. Leiten Sie es nicht vom Theme ab, schauen Sie sich die Seite an, auf der der Kunde tatsächlich ist.
04

Eine externe Zahlungsweiterleitung bricht die Sitzung ab

Wenn der Checkout an ein externes Gateway übergibt und den Kunden auf eine Bestellbestätigungsseite zurückschickt, kann dieser Umweg die Browsersitzung abbrechen, von der das Pixel abhängt. Der Kauf wird abgeschlossen, der Kunde sieht seine Bestätigung, und das Event erreicht Snapchat nie oder kommt ohne die Kennungen an, die für die Zuordnung nötig sind.

An diesem Punkt reicht ein reines Browser-Setup nicht mehr aus. Server-Side Tracking über die Conversions API ist die dauerhafte Lösung, weil das Event von Ihrem Server ausgeht und nie davon abhängt, eine Weiterleitung zu überleben.

Der CheckVerlässt Ihr Zahlungsablauf Ihre Domain? Wenn ja, betrachten Sie reines Browser-Tracking als Versuch und planen Sie CAPI ein.
05

Ein Single-Page-Checkout initialisiert das Pixel neu

Wenn in Single-Page-Anwendungen die Pixel-Initialisierung bei jedem virtuellen Seitenaufruf läuft, wird der Zustand des Pixels jedes Mal zurückgesetzt. Früher im Ablauf gesammelte Daten für den erweiterten Abgleich gehen verloren, und das Purchase-Event kommt ohne die Kennungen an, die es nützlich machen: dünn, schlecht zugeordnet und manchmal gar nicht zugeschrieben.

Das Event wird ausgelöst. Es trägt nur nicht, was es braucht, und deshalb wird dieser Fehler leicht als „funktioniert“ missverstanden.

Der CheckBeobachten Sie den Network-Tab durch den ganzen Checkout. Die Initialisierung sollte einmal passieren. Events sollten viele Male ausgelöst werden.
06

Die Deduplizierung frisst das Event

Wenn Sie das Pixel und die Conversions API betreiben (was Sie sollten), dedupliziert Snapchat anhand von client_dedup_id (48-Stunden-Fenster) oder transaction_id (30 Tage). Zwei Events mit derselben Kennung werden absichtlich einmal gezählt.

Zum Problem wird es, wenn sich Browser und Server bei dieser Kennung nicht einig sind. Ist die Zuordnung falsch, zählen Sie entweder alles doppelt oder verlieren still eine Seite. Laut Snap gehören Events ohne Kauf zu client_dedup_id und Purchase-Events zu transaction_id, und entscheidend ist: Der Wert muss auf jedem Weg, der dieses Event sendet, übereinstimmen.

Der CheckErfassen Sie für eine Bestellung die Kennung, die der Browser gesendet hat, und die, die Ihr Server gesendet hat. Sie müssen identisch sein. Nicht ähnlich: identisch.

Was ich Ihnen nicht sagen kann

Zwei ehrliche Einschränkungen, denn ein Artikel, der keine zugibt, verbirgt meist welche.

Ich kann Ihnen keine Häufigkeitsrangliste aus einer großen Stichprobe geben. Die Reihenfolge oben spiegelt eine kleine Zahl von Konten wider, plus das, was die Fehlerarten logisch nahelegen. Ein kleingeschriebener Event-Name bricht das Reporting zuverlässig, deshalb gehört er nach oben, egal wie oft ich ihn selbst gesehen habe. Verstehen Sie die Rangliste als sinnvolle Suchreihenfolge, nicht als Statistik.

Die Oberfläche von Snapchat ändert sich. Menüpfade veralten schnell, deshalb sind die Checks oben am Netzwerk-Request und am Payload festgemacht statt daran, wo ein Button gerade sitzt. Der Payload ist das, was tatsächlich stimmt.

Die Kurzfassung

  1. Öffnen Sie den Network-Tab, filtern Sie nach tr.snapchat.com, geben Sie eine Testbestellung auf.
  2. Prüfen Sie, ob der Event-Name genau PURCHASE lautet, großgeschrieben.
  3. Prüfen Sie, ob transaction_id vorhanden und pro Bestellung eindeutig ist.
  4. Prüfen Sie, ob das Pixel auf der Seite existiert, auf der der Kunde tatsächlich landet.
  5. Wenn der Checkout Ihre Domain verlässt, planen Sie die Conversions API ein.
  6. Wenn Sie Pixel und CAPI betreiben, prüfen Sie, ob die Deduplizierungskennung auf beiden Seiten genau übereinstimmt.

Wenn Sie alle sechs durchgegangen sind und das Event immer noch nicht ankommt, liegt das Problem meist nicht am Pixel, sondern daran, dass die getestete Seite nicht die Seite ist, die Ihre Kunden erreichen. Gehen Sie zurück und schließen Sie einen echten Kauf mit echtem Geld ab, auf einem Handy, nach einem Anzeigenklick. Testbestellungen über einen Staging-Link überspringen genau die Teile, die kaputtgehen.
